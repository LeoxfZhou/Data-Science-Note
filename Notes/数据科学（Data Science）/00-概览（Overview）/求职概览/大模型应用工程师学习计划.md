# 大模型应用工程师学习与求职路线图

> 目标：以 Python、FastAPI、RAG、Agent 和工程化部署为主线，达到初级大模型应用工程师（LLM Application Engineer）常见岗位的可投递基线。
>
> 当前策略：不以纯算法、大模型预训练为当前目标；保留已有 Java 后端经历，但暂不要求重新掌握完整 Spring 技术栈。
>
> 预计周期：约 24～30 周（每周 15～20 小时）。时间只是参考，必须通过验收才能进入下一阶段。

## 0. 使用说明

### 0.1 状态标记

- `⬜`：未开始
- `🟨`：学习中
- `🔎`：做过或学过，等待验收
- `✅`：已通过验收
- `❌`：验收未通过，需要补强
- `🔄`：以前掌握，现在需要复习
- `⏸️`：暂缓，不阻塞当前主线
- `⭐`：Optional，不计入主线完成率

Markdown 勾选规则：

- `- [ ]`：尚未通过
- `- [x]`：已经通过验收
- 验收失败时不要勾选，在条目后标记 `❌` 并记录缺口。
- “看完课程”“复制代码运行成功”“跟着教程做完”不能单独作为通过依据。

### 0.2 验收证据

技能或项目通过时，至少保留一种证据：

- Git commit 或仓库链接
- 可运行的代码
- 自动化测试结果
- 项目 README
- 实验报告或评测结果
- 演示视频或截图
- 能独立回答该项目的验收问题

### 0.3 更新流程

1. 一次只推进“当前任务”。
2. 完成后报告任务编号，例如：`完成 S3-P1`。
3. 根据任务验收标准检查代码、运行结果和理解程度。
4. 通过后改成 `[x]` 和 `✅`，填写完成日期及证据。
5. 未通过则标记 `❌`，记录最小补救任务，不直接进入下一关。
6. 每完成一个阶段，更新总进度和下一个阶段。

### 0.4 完成路线图意味着什么

完成全部非 Optional 项目后，应当能够：

- 使用 Python 和 FastAPI 开发大模型后端服务。
- 调用云端模型和本地模型，处理流式输出、结构化输出、超时与错误。
- 独立实现、评测并优化 RAG 系统。
- 使用 PostgreSQL/pgvector、Redis、Docker 等常见工程组件。
- 实现具有工具调用、状态管理和失败处理的 Agent/工作流。
- 处理基础的安全、监控、成本和部署问题。
- 拿出至少两个可以展示、可以复现、可以深入讲解的求职项目。

这代表覆盖初级岗位的大部分常见技能，但不等于保证获得 Offer；简历、岗位数量、项目质量、面试表达和投递策略同样重要。
