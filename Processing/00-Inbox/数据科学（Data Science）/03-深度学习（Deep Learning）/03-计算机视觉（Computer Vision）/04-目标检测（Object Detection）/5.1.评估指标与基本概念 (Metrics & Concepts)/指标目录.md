
## 一、 基础砖石：混淆矩阵与四大基本元素

在目标检测中，我们首先需要判定一个预测框到底是“猜对了”还是“猜错了”。这通常由**置信度阈值**和**IoU阈值**共同决定。

- **TP (True Positive, 真正例)**：预测框与真实框的 **IoU $\ge$ 设定阈值**（且类别正确）。模型成功检测到了目标。
- **FP (False Positive, 假正例)**：预测框与真实框的 **IoU < 设定阈值**，或者预测了多余的无用框、弄错了类别。俗称“虚警”或“误检”。
- **FN (False Negative, 假负例)**：真实目标完全被模型漏掉了，没有对应的预测框。俗称“漏检”。
- **TN (True Negative, 真负例)**：模型正确地把背景判定为背景。_注：在目标检测中，由于潜在的背景区域无限大，TN 通常不参与核心指标的计算。_

## 二、 几何重叠度：IoU 及其家族 (Localization Quality)

用于评估模型定位的精准度，即预测边框（Box A）与真实边框（Box B）的贴合程度。

### 1. 标准 IoU (Intersection over Union, 交并比)

$$IoU = \frac{\text{Area}(A \cap B)}{\text{Area}(A \cup B)}$$

- **解释**：两个矩形框的**交集面积**除以**并集面积**。取值范围 `[0, 1]`。
- **痛点**：若两个框完全不重叠，IoU 直接归零，此时无法反映两个框到底距离有多远。

### 2. 进化家族（兼作评估与损失函数）

- **GIoU**：引入了能包含两框的最小闭包矩形 $C$，计入了不重合时的距离梯度。
- **DIoU**：直接引入了两框中心点的**欧氏距离**，定位收敛更直接。
- **CIoU**：在 DIoU 的基础上，进一步加入了长宽比（Aspect Ratio）的惩罚项，是目前评估边框完备性最成熟的几何指标。

## 三、 矛盾的孪生兄弟：Precision 与 Recall

这两个指标相互制约，如同天平的两端。

### 1. Precision (精确率 / 查准率)

$$Precision = \frac{TP}{TP + FP}$$

- **直观解释**：**在模型所有预测为目标的框里，究竟有多少是猜对的？**
- **应用侧重**：侧重“说话要准”。高 Precision 意味着模型很谨慎，不轻易报喜，一旦报警就大概率是真的。常用于对虚警极其敏感的场景（如反垃圾邮件、高精度工业缺陷剔除）。

### 2. Recall (召回率 / 查全率)

$$Recall = \frac{TP}{TP + FN}$$

- **直观解释**：**在整个数据集中所有真实存在的目标里，模型成功捞回来了多少？**
- **应用侧重**：侧重“宁错杀不放过”。高 Recall 意味着模型广撒网，哪怕多抓错一些，也绝不漏掉一个。常用于对漏检零容忍的场景（如自动驾驶行人检测、医疗影像肿瘤筛查）。

### 3. F1-Score (平衡分数)

$$F1 = 2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}$$

- **直观解释**：Precision 和 Recall 的**调和平均数**。当二者出现严重偏科时，F1-Score 会很低；只有二者均高时，F1 才会处于高位。

## 四、 黄金统治标准：AP 与 mAP

单一的 Precision 和 Recall 只能反映模型在某个固定置信度阈值下的表现。为了全面评估模型在所有阈值下的综合实力，引入了 AP 和 mAP。

### 1. P-R 曲线 (Precision-Recall Curve)

通过从高到低调整模型的置信度阈值，我们可以得到一系列不同的 Precision 和 Recall 值。以 Recall 为横坐标，Precision 为纵坐标绘制出的曲线，就是 P-R 曲线。

### 2. AP (Average Precision, 平均正确率)

$$AP = \int_{0}^{1} P(R) \, dR$$

- **直观解释**：P-R 曲线下方的**面积**。AP 衡量的是模型对**单一类别**的检测能力。面积越接近 1，说明该类别的检测性能越完美。

### 3. mAP (mean Average Precision, 平均正确率均值)

$$mAP = \frac{1}{N} \sum_{i=1}^{N} AP_i$$

- **直观解释**：把所有类别（共 $N$ 类）的 AP 值加起来取平均。**它是衡量全品类目标检测器综合性能的绝对核心指标**。

### 4. 工业与学术界最常见的两种 mAP 评判标准 (以 COCO 数据集为例)

- **mAP@0.5 (或简写为 $AP_{50}$)**：
    - **定义**：将 IoU 阈值严格固定为 0.5 时计算出的 mAP。
    - **解释**：只要预测框与真实框重叠了一半以上，就算检测成功。这个指标主要考察模型**有没有找对地方、有没有认对类别**，对边框定性的精准度要求相对宽松（YOLOv3 时代的核心指标）。
- **mAP@0.5:0.95 (或在 COCO 中直接缩写为 $AP$)**：
    - **定义**：在 IoU 阈值从 0.5 开始，以 0.05 为步长递增到 0.95（即 0.5, 0.55, 0.6, ..., 0.95共 10 个阈值），分别算出 10 个 mAP，最后再对这 10 个 mAP 取平均。
    - **解释**：这是目前顶会打榜、学术界以及严苛工业界最认可的“完全体”指标。它极度看重模型**贴合边界的丝滑程度**。如果你的模型只能把框粗略套住（IoU 只有 0.6），在这个指标下得分会非常惨淡。

## 五、 工业落地维度：速度与能耗指标

模型仅有高 mAP 还远远不够，在实际工程落地中，必须兼顾算力资产的开销。

- **FPS (Frames Per Second, 每秒帧数)**：模型每秒钟能处理多少张图片。FPS > 30 通常被视为实时检测的门槛（如 YOLOv5s 在批处理下可达 140 FPS）。
- **Latency (推理时延)**：处理单张图片所需的时间，通常以毫秒（ms）为单位。时延与 FPS 互为倒数，但时延更能直接反映单次响应的敏捷度。
- **Parameters (参数量)**：模型中所有需要训练的权重参数总和。直接决定了导出的模型文件有多大（如 27MB 或 367MB），决定了设备**内存/显存**能不能塞得下。
- **FLOPs (Floating Point Operations, 浮点运算数)**：衡量模型计算复杂度的指标。FLOPs 越高，说明模型对芯片算力（GFLOPS/TFLOPS）的压榨越狠，直接关系到设备的功耗、发热量以及电池续航。
